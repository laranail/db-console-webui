# Release

How a version of `laranail/db-console-webui` is cut, and what each release carries.

## Versioning

Releases follow [Semantic Versioning](https://semver.org/) on the `0.1` line, so consumers require
`laranail/db-console-webui ^0.1`. Each version is its own tag; `v0.1.0` is never moved. The
`dev-main` branch alias is `0.1.x-dev`.

## Cutting a release

1. Branch `release/vX.Y.Z` from `main`.
2. In one commit named `Release X.Y.Z`, rename `## [Unreleased]` in `CHANGELOG.md` to
   `## [X.Y.Z] - <date>`, open a fresh empty `## [Unreleased]` above it, and update the compare links
   at the foot of the file.
3. Open a pull request and merge it with a merge commit once every check is green.
4. Tag the merge commit `vX.Y.Z` and push the tag.

Pushing the tag runs `.github/workflows/release.yml`, which publishes the GitHub release.

## What the release workflow does

| Step | Result |
|---|---|
| Install runtime dependencies | `composer install --no-dev`, the set a consumer installs |
| Generate CycloneDX SBOM | `db-console-webui.cdx.json`, from that install |
| Extract release notes | the `## [X.Y.Z]` section of `CHANGELOG.md`, as the release body |
| Create GitHub release | the body above plus GitHub's generated contributor list, with the SBOM attached |

A tag whose version has no `CHANGELOG.md` section still publishes, with a body that points at the
changelog, so keep the section and the tag in step.

## The SBOM

An SBOM (software bill of materials) lists every component a release ships with, by name, version
and licence, in a machine-readable form. It lets a consumer check a release against vulnerability
advisories or a licence policy without installing it.

Each release attaches one in the [CycloneDX](https://cyclonedx.org/) JSON format, generated by
[anchore/sbom-action](https://github.com/anchore/sbom-action) (Syft) from the `--no-dev` install, so
it describes the runtime dependency tree and not the test tooling. The file is named after the
repository, `db-console-webui.cdx.json`: the workflow derives it from `github.event.repository.name`,
so a copy of the workflow in another package names its own.

> Release v0.1.1 attached it as `db-console.cdx.json`, a name copied from laranail/db-console. The
> contents describe db-console-webui; only the filename is wrong. Releases after it use the derived
> name.

Download it from the release page, or:

```bash
gh release download v0.1.1 --repo laranail/db-console-webui --pattern '*.cdx.json'
```
